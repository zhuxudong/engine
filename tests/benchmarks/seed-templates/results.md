# Seed 樱花与沙漠的桌面 WebGPU 基准

基于 `dev/2.0` 的最终渲染器版本为 `35b6c4547`。两个模板取自 `experimental/engine-next` 的 `92ea60eae`。两端加载相同的樱花 `sakura-pearl`、沙漠 `titan-wasteland` 项目及原始发布资产。比较包含真实草地、岩体、动物、灯光、阴影、水体、屏幕空间反射（SSR）和 Bloom。模板集成修订 `12c41cd38` 和 `23c264df8` 对齐了反射接收区域和湿地材质的屏幕坐标。[复现方法](README.md)

在这台 Mac 上，樱花完整场景的平均硬件 GPU 忙时下降 15.1%，沙漠上升 5.2%。单看每帧 CPU 更新或排空队列后的端到端吞吐，WebGPU 均未取得整体领先。两次沙漠访问的 GPU 忙时变化方向相反。

## 测量方法

主机使用 Apple M5 Pro（20 核 GPU）、macOS 26.3.2 和 Chromium 140.0.7339.16。两端均为 960 × 540、DPR 1，使用相同世界种子、五个相机关键帧和固定 1/60 秒的模拟步长。显示刷新间隔、引擎 CPU update 和硬件 GPU 忙时分别采集。硬件计时取 Metal System Trace 中 Chromium GPU 进程在每个帧窗口处于 Active 的时间，各硬件阶段的重叠区间只累计一次。硬件录制每次新开世界，预热 90 帧、记录 120 帧。20 对录制共得到 4,800 个有效帧窗口，热状态均为 Nominal。每对使用同一本机浏览器 GPU 进程，完整模板交替访问顺序并各重复两次。独立的 CPU 和吞吐量访问各记录 180 帧。API 计时器的计时边界随图形 API 不同，只用于各自后端的诊断。[硬件计时方法](metal/README.md)

## 地形遮挡的实际收益

| 固定视点 | 视锥候选 → 地平线筛选后 | WebGL2 GPU 忙时，关闭 → 开启 | WebGPU GPU 忙时，关闭 → 开启 |
| --- | ---: | ---: | ---: |
| 樱花 | 300 → 9 | 4.226 → 5.153 ms | 3.775 → 3.311 ms |
| 沙漠 | 223 → 131 | 2.620 → 3.257 ms | 2.724 → 2.361 ms |

这两个机位开启遮挡后，WebGPU 的平均 GPU 忙时分别下降 0.464 和 0.363 ms。同期 WebGL2 也剔除了相同数量的岩体，但该轮 GPU 忙时上升。每个开关各测一次，候选数下降能稳定复现，耗时变化仍受负载影响。两个视点都保留了视锥剔除与 LOD。上述候选仅指岩体，樱花地平线剔除 75 个岩体分组、291 个实例，沙漠剔除 33 个分组、92 个实例。[固定视点与计数定义](horizon/README.md)

## 图像复核

- 樱花完整镜头的两端图像平均 RGB 差为 2.31/255，任一通道误差超过 20 的像素占 3.45%，局部亮度 SSIM 为 0.911。
- 沙漠完整镜头的两端图像平均 RGB 差为 1.19/255，任一通道误差超过 20 的像素占 1.15%，局部亮度 SSIM 为 0.978。

12 个模板和开关组合中，8 个达到静态画廊的图像阈值。樱花关闭 Bloom 后平均 RGB 差为 4.50/255，6.93% 像素有通道误差超过 20，树冠超限像素的 79.34% 位于原始图像的边缘，两处岩石、平地、树干内部的均差均低于 0.07/255。树冠和部分前景的残差原因尚未确认。沙漠隐藏植被层级后全帧为 7.38/255、11.58%，差异集中在动物所在区域。独立关闭动物层级时，两端全帧均差为 0.43/255，超限像素为 0.31%。这些画面均保留原始输出，未按遮罩排除像素。

原始 PNG 包含运动中的动物、云、水及预算内异步发布的细节。完整镜头反映实际场景复现误差。每项还记录镜头路径、真实效果开关、运行日志和三帧几何计数。沙漠水面区域另有原生逐阶段读回验证。

## 渲染器与模板的分工

| 模块 | 切换后端时实际执行的工作 | 希望进一步提速时，工作应落在哪里 |
| --- | --- | --- |
| 草地、自然植被 | Seed 自己读取密度、高度并选择草地 LOD。它使用引擎的反馈接口生成记录，WebGL2 执行 transform feedback，WebGPU 在引擎内部执行 compute。普通树木与灌木沿用相同的合批条件，历史 shader 在两端都可走实例绘制。 | 引擎可以合批绘制已提交的实例。将可见性计算也交给 GPU 需要可复用的实例记录、分组边界和可见列表。 |
| 地形遮挡 | Seed 在 CPU 上结合高度场和岩体分组测试地平线，两端执行同一算法。 | 原生遮挡查询允许在没有 compute shader 的情况下测试代理几何体。实例很多时可另用 Hi-Z、compute 和间接绘制，避免将每个实例的可见结果读回 CPU。 |
| SSR | 现有管线构建深度金字塔、追踪并合成反射。切换后端需要渲染器统一裁剪和采样坐标。 | 追踪算法和画质参数决定主要成本。若采用 compute，可以在效果实现内接入，复用场景原有的反射接收材质。 |
| Bloom | 两端都执行既有的多级降采样/上采样全屏绘制。 | 引擎的后处理实现可以改变绘制或计算的组织方式，场景仍使用同一 Bloom 配置。 |

WebGPU 的深度测试会拒绝被遮住的片元。对象级遮挡查询则要求应用或引擎在绘制时显式记录，异步获取是否有样本通过。WebGL2 同样提供 `ANY_SAMPLES_PASSED`。在另一种 GPU 驱动的实现中，compute 批量读取分层深度、写可见实例及间接参数，再由 `drawIndexedIndirect` 消费。Seed 当前的 SSR 深度金字塔服务于反射，岩体地平线测试发生在 CPU。[WebGPU 遮挡查询](https://www.w3.org/TR/webgpu/#occlusion-query) · [WebGL2 查询](https://registry.khronos.org/webgl/specs/latest/2.0/) · [WebGPU 间接绘制](https://www.w3.org/TR/webgpu/#dom-gpurendercommandsmixin-drawindexedindirect)

## 用真实场景发现的引擎问题

- 历史 shader 的实例化变体曾退回逐个物体提交。修复后，樱花中段的一次检查从 341 个原生 WebGPU draw 降至 162 个，同一镜头的 WebGL2 为 152 个。两端主前向和阴影着色器分别为 94 和 30 个 draw，草地实例均为 23,240 个。原生 draw 还包含后端生成 mip 等辅助工作。
- 私有 uniform 缓冲的回收曾将同帧更新拆分成大量复制和渲染 pass。修复前，樱花中段抽查记录了 196 次 buffer-to-buffer 复制、120 段 Camera Forward。修复后，该帧为 0 次复制和一段 Camera Forward。公共缓冲的 Discard 语义由独立回归用例覆盖。
- 沙漠水面暴露了 SSR 裁剪的纵轴错误。在 480 × 270 的追踪纹理上，正确接收区域覆盖下方 120 行，原 WebGPU 实现选中了上方 120 行。在同一水面区域读回 736 个追踪像素，WebGL2 原始命中 714 个，WebGPU 修正前为 0，修正后为 715 个，两端最终历史合成均有 735 个有效像素。2,835 个呈现水面像素的平均 RGB 差从 20.83/255 降至 0.47/255。历史湿地 shader 的屏幕采样方向也已对齐，仅更新原有编译指令中的坐标表达式。
- 沙漠的动画骨架实际使用 21–43 根骨骼，shader 按设备上限声明 1,012 个 mat4。中段抽查 29 次矩阵打包，共处理 1,878,272 字节的声明容量，其中实际骨骼数据为 49,600 字节。引擎现在一次补零连续数组的未用部分，WebGPU 根据每个物理缓冲中已验证的零区间减少上传。缩短骨架时仍覆盖上一对象的脏尾，轮换、恢复或外部写入后会重新验证。shader 指令、绑定长度以及材质保持原样。[CPU 打包实现](../../../packages/core/src/shader/Std140FieldWriter.ts) · [完整缓冲语义回归](../../src/rhi-webgpu/SparseUniformArray.test.ts)

对沙漠做同一路线的 WebGPU 优化前后验证。三帧实际 `queue.writeBuffer` 的总字节数分别从 3,836,700、2,215,700、3,761,508 降到 423,060、393,628、431,076。中段写入次数从 201 增到 228，原因是大型矩阵数组前后的其他有效字段仍须提交。单独开启 CPU 采样时，177 帧中 `Std140FieldWriter.write` 的自耗时从 281.1 ms 降至 76.3 ms，对应访问的引擎更新中位数从 8.8 ms 降至 6.1 ms。再次独立运行优化版时，中段上传 399,012 字节、共 230 次，CPU 更新中位数为 7.6 ms。两次都重现了传输量下降，CPU 降幅随访问而变。这里比较的是同一 WebGPU 后端的两份引擎版本。修复保留了历史 shader 的声明长度，以便自定义 shader 继续按原索引读取。
